# Contributing to Lune 🌙

Thank you for your interest in contributing to **Lune**! We welcome contributions from developers, designers, translators, and healthcare advocates of all backgrounds.

---

## Code of Conduct

We are committed to providing a welcoming, respectful, and safe community for everyone. Please be courteous, inclusive, and professional in all discussions and pull requests.

---

## How Can You Contribute?

### 1. Reporting Bugs
- Search existing [Issues](https://github.com/Ssohebmerr/lnunr/issues) before opening a new one to avoid duplicates.
- Provide clear steps to reproduce the issue, your device OS and Flutter version, and expected vs actual behavior.

### 2. Suggesting Enhancements
- Open an Issue describing the feature, why it is useful, and how it aligns with Lune's privacy-first values.

### 3. Improving Translations
- Lune supports 21 languages! If you notice translation errors or awkward medical phrasing in any language, contributions to `menstrual_cycle_widget-master/lib/widget_languages/` and `cycle_app/lib/l10n/` are warmly appreciated.

### 4. Submitting Pull Requests
1. **Fork** the repository and create your branch from `master` or the target feature branch.
2. Follow standard Flutter/Dart coding conventions (`flutter analyze`).
3. Ensure all existing tests pass:
   ```bash
   flutter test
   ```
4. If you introduce new features or logic, add corresponding unit or widget tests.
5. Submit a pull request with a clear description of the changes made.

---

## Commit Guidelines

We use conventional commit messages to keep the history readable:
- `feat: ...` for new user-facing features
- `fix: ...` for bug fixes
- `docs: ...` for documentation improvements
- `refactor: ...` for code structure changes without feature alteration
- `test: ...` for adding or updating tests
